# 技术说明

这份文档保留 README 中省略的实现细节，面向想调试、扩展或适配其他设备的开发者。

## 数据流

1. 在本机读取 Codex 会话、侧栏标题、未读状态和额度。
2. 将状态归并为任务、额度、提醒和设备状态。
3. 按横版或竖版布局生成单色位图，并计算 SHA-256。
4. 位图有变化时，通过 BLE 连接读取设备状态并写入图片；没有变化时不扫描、不连接蓝牙。

电脑和墨水屏之间是蓝牙无线连接，程序不会刷写固件，也不会开放 HTTP/LAN 服务。

## 事件刷新

- 监听 Codex 会话文件、侧栏标题索引和未读状态文件。
- 开始运行、计划步骤变化、完成、失败或未读标记变化后，进入 1 秒静默合并窗口。
- 合并窗口结束后立即重算画面和额度。
- BLE 写入期间到达的事件会保留，上传结束后再次检查。
- 活跃任务 30 秒、空闲 60 秒轮询作为文件事件遗漏和无本地事件额度变化的兜底。
- `state_5.sqlite` 与 `logs_2.sqlite` 只读取标题和活跃线程，不作为监听源，避免额度读取触发自身循环。

1 秒是事件合并和刷新触发窗口，不是屏幕已经完成更新的保证。墨水屏的全屏物理刷新通常还需要几秒，具体取决于刷新波形、蓝牙传输和重试情况。

## 额度处理

- 屏幕显示实时接口返回的精确整数剩余百分比。
- 一次实时额度读取失败时，保留上一次成功读取的实时值，避免屏幕跳回旧值。
- API 账户模式显示 `API`，不读取 ChatGPT 主额度。
- 竖版右上角显示周额度重置日期 `M.D`；优先使用 `secondary` 周窗口，没有时回退到可用窗口。

## BLE 图片协议

- 内容变化时建立一次 BLE 连接：读取设备状态、按电压滞回规则重渲染、在同一连接内写图。
- 一帧图片发送 22 个 129 B 图像包，最后发送 `0x62` 提交命令。
- 断线或瞬时 GATT 错误时，从整帧开头重传，默认最多重试 2 次。
- 连接后再次检查分辨率、状态包和 MTU；不匹配时拒绝写入。

## 竖版布局

- 逻辑画布为 104×212，上传前旋转为设备要求的 212×104。
- 顶部显示全局状态和额度重置日期；任务区最多 6 行，超出用 `...`。
- 底部状态条最多 8 格，按 4×2 排列。
- 运行任务显示圆点或真实 `当前步骤/总步骤`；完成和失败只显示仍未读的 `✓` / `×`。
- 完成和失败状态最多保留 2 小时；在 Codex 中读掉未读标记后会提前消失。
- 运行、对勾和叉号使用复用的 7×7 单色像素字形，不依赖 Unicode 字体。

## 自动启动

`install-task.ps1` 注册当前用户登录任务。任务单实例运行，异常退出最多自动重启 3 次；每分钟看门狗触发一次恢复检查。电脑睡眠时任务暂停，唤醒后由 Windows 补跑，不会主动唤醒或重启电脑。

## 隐私边界

完整配置 `config.json`、日志和实时预览只保留在本机，不应提交到公开仓库。程序只把摘要画面发送到本机蓝牙设备，不上传完整 prompt、回复或会话内容。
